把 CPM 的重复流程，做成可复用的 业务工具

在 Momenta 客户项目管理实习期间，我围绕自驾量产项目协同中的信息同步、任务追踪、文档生成与进度复盘等高频场景，设计并搭建了轻量化工具原型。由于项目涉及内部业务流程与客户信息，本页仅展示脱敏后的界面截图与产品设计思路，不展示源代码、真实业务数据或内部文档。

为什么这样展示？

相比直接展示程序或代码，这里用“问题 - 方案 - 能力”的方式说明我的工作贡献：既能让访问者理解工具价值，也能避开保密风险。

Role
CPM 实习生 / 业务工具设计
Scenario
客户项目管理、跨部门协同、周报复盘
Method
Claude Code + Skill + 前后端页面设计
Value
减少重复沟通，提升进度同步与信息处理效率
Tool 01

CPM Agent：面向日常业务的 AI 工作助手

问题: Claude Code 的终端操作模式无法完全适配 CPM 日常业务场景，业务同学更需要结构化、低门槛、可重复使用的流程入口。
方案: 通过 Skill 搭配前后端交互设计，把飞书文档、日程安排、代码编写、记录查询等高频动作封装成更贴近业务语境的工作台。
我的贡献: 梳理业务场景与输入字段，设计工具工作流、交互入口与信息输出形式，让 AI 能更稳定地服务具体 CPM 流程。
Tool 02

项目进度看板：让团队进度、风险与周报自动浮现

问题: 多车型、多任务、多负责人并行推进时，进度分散在不同沟通链路中，容易出现信息滞后、延期风险发现不及时。
方案: 搭建项目看板，将任务、负责人、状态、DDL 与延期情况统一可视化，并提供筛选、统计、告警与周报生成功能。
我的贡献: 从 CPM 管理视角定义字段、状态和看板逻辑，围绕“追踪 - 告警 - 复盘”设计闭环，提高团队同步效率。
展示边界: 本页仅用于说明我在实习中的产品思考、业务工具设计与效率优化能力。截图已作为界面示意使用，详细业务规则、客户信息、真实项目数据与代码实现均不在网页中展示。
